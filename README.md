# audiobooksync

This repo contains a proof of concept for a whispersync-like experience in audiobookshelf. It is not meant to be production quality or published upstream as-is. Don't expect updates or support.

The goal is achieved in two steps:
1. Generate sync files alongside the ebook.
2. Modify the clients to load this file and highlight the word currently being read.

No server code change is needed. If you only use your phone to read, you only need to run the python script once and use the modified APK. The client code went through significant changes: the epub.js reader was replaced with foliate-js. I tried to keep feature parity, but I might have missed something.

Supports only epub. Audio split across multiple files is not supported. English only.

## Creating `.smil` files

Install uv:
```
winget install --id=astral-sh.uv  -e
```

Run:
```
uvx --from git+https://github.com/Nodja/audiobooksync abs-sync "S:\media\audiobooks"
```
Replace the folder with wherever you keep your audiobookshelf library.

The first run installs a bunch of dependencies and download a ~650MB CTC model (`parakeet-ctc-0.6b`) from Hugging Face. Later runs start generating right away.

Repeated runs skip books that already have a `.smil` file, so you can run the command again whenever you add books to your library. You can cancel it mid-run; the only progress lost is the book currently being aligned.

Speed depends on your GPU. The biggest book I have (62 hours) took 20 minutes on my 5060 Ti. Normal-sized books take 2-5 minutes. If GPU acceleration doesn't work for some reason, expect it to take about 10x that.

## Reading the synced books

1. Trigger a library scan in audiobookshelf. On the web client you'll see a `.smil` file listed under the "Library files" section of an audiobook.
2. Install a modified client:
   - **Android:** download the APK from the releases and sideload it. It installs alongside the official client so you can have both installed at the same time. It's a debug build so you might get some scary prompts when installing.
   - **iOS:** you're out of luck. I don't own a Mac to build and test the client, so you'll have to build it yourself and hope it works.
   - **Web:** download the zip from the releases and replace the `client/dist` folder of your install. I use docker, and my docker-compose looks like this:

     ```yaml
     services:
       audiobookshelf:
         image: ghcr.io/advplyr/audiobookshelf:2.37.0
         container_name: audiobookshelf
         hostname: audiobookshelf
         restart: always
         volumes:
           - /tank/storage/media:/media
           - ./config:/config
           - ./metadata:/metadata
           - ./audiobookshelf-client-sync-web:/app/client/dist
         environment:
           - AUDIOBOOKSHELF_UID=1000
           - AUDIOBOOKSHELF_GID=1000
           - TZ=America/New_York
     ```

If you only read on Android and you have your abs server open to the wide web, I recommend you don't use the web client. ABS updates might break it and you'll also be missing security updates.

Source code for the clients are in branches. [client-web](../../tree/client-web) [client-mobile](../../tree/client-mobile)

## Implementation details

### The `.smil` file

SMIL is the format behind the EPUB 3 standard's Media Overlays, and it normally lives inside the epub itself. One of my goals was to use my existing files as-is, so adding a file alongside the epub instead of generating a huge epub3 made the most sense to me.

The standard only covers sentence timings. The `.smil` file generated by this tool extends it with a `data-word-timestamps` attribute holding a JSON array of each word's timings.

### Aligning the audio

The trigger for me creating this project was when I learned about pytorch's CTC forced alignment and ran a proof of concept that showed very promising results. Requiring pytorch however, would never fly for a project like ABS. So I had Claude use an ONNX model and re-implement much of it. The current implementation should be easily portable to transformers-js.

The project went through 3 major revisions in a couple of days as edges cases propped up, things grew overly complex, and we generalized. I won't claim I understand any of the code, I merely steered claude into exploring simpler solutions, which ended up with the current state of the aligner. The rest of this section is claude's explanation of how it works of which I can only claim points 5 and 6 as my own.

> The audio is aligned with NVIDIA's Parakeet CTC 0.6b, exported to ONNX (`onnx-community/parakeet-ctc-0.6b-ONNX`) and run with onnxruntime on the GPU when one is available.
>
> The model emits one set of character probabilities every 80 ms, and the audio is processed in 120 second chunks.
>
> Forcing the whole book onto the whole audio in one go breaks as soon as the audio and the text disagree, and they always do somewhere: spoken credits, a different edition, a missing footnote, an illustration the narrator skips. So the book is consumed left to right with an anchor step in front of the alignment:
>
> 1. **Finding the start.** The first three minutes are transcribed, and the transcript is looked up in a word-trigram index of the book. The place with the most matching trigrams is where the narration begins, which skips publisher credits and intros.
> 2. **Anchoring.** For each chunk, the model's own greedy transcript is diffed against the text at the cursor. Runs of at least four matching words become anchors that tie a stretch of text to a stretch of audio. Isolated matches that disagree with their neighbours about where in the book they are, such as a repeated phrase, are dropped.
> 3. **Forced alignment.** The words between anchors are aligned with a CTC Viterbi search to get a start and end for each word. Text the narrator doesn't say is dropped rather than squeezed onto unrelated audio, and so are audio stretches that match nothing in the book.
> 4. **Advancing.** The cursor moves to the last word placed, and the next chunk starts where that word ended. If a chunk matches nothing it is reported and skipped.
> 5. **Second pass.** Audio the first pass couldn't place is searched for again across the whole book, among the words that still have no timing. This is for chapters narrated out of order, such as acknowledgements read last but printed first.
> 6. **Cleanup.** Words with a poor fit are dropped, up to three untimed words between two timed ones are given a share of the time between them, and every stretch of text that still has no timing is listed in the warnings.
>
> What's left untimed is mostly text that really differs between the audiobook and the epub, and the end credits.

### The clients

The official mobile and web clients use a Vue 2 component built on epub.js to parse the epub. epub.js is badly outdated and can't display overlays, so the reader component was replaced wholesale with one using [foliate-js](https://github.com/johnfactotum/foliate-js), which is vendored in for development convenience. foliate-js itself is unmodified.

My goal was to replicate the functionality and look of the official reader, then add the highlighting on top. I hope nothing was left behind; the official reader was pretty limited, so I don't think anything was missed.

While audio plays, the reader turns pages to follow narration, treating audio progress as the only source of progress. This gets in the way of navigating the book unless you pause the player. Clicking a word on the web client, or double-tapping it on mobile skips the audio to that word.

The `.smil` file is downloaded when loading the `.epub`, so if you plan on reading offline, open the book in the reader first. `.smil` files are uncompressed XML and take up ~500KB per hour of narration, so keep that in mind. The files are cached locally in IndexedDB with a 15MB limit, the cache compressed the files so it should be able to handle more than 10 books easily, the cache evicts the oldest book by when they were last read. This caching strategy might run into issues, so an official implementation should handle the downloads differently.
